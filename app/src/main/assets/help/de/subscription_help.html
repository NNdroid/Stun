Ein Abo ist nichts weiter als eine HTTPS-Adresse. Stun holt die Knotenliste von dort und importiert, aktualisiert oder entfernt Knoten auf diesem Gerät automatisch.

1. Die Adresse

  • Nur https:// wird akzeptiert. Reines http, ftp und sftp werden abgelehnt — der Abo-Inhalt bestimmt, mit welchen Servern du dich verbindest; über einen unverschlüsselten Kanal könnte ihn jeder unterwegs komplett umschreiben.
  • Dieselbe Adresse wird nur einmal gespeichert. Erneutes Hinzufügen aktualisiert den vorhandenen Eintrag, statt einen zweiten anzulegen.

2. Unterstützte Dateiformate

Stun probiert die folgenden Formate der Reihe nach durch und bricht beim ersten ab, das Knoten liefert. Gemischte Inhalte werden nicht unterstützt.

2.1 Ein stun://-Knoten pro Zeile

Das häufigste Format — genau der Text, den „Als Text teilen“ für einen einzelnen Knoten liefert, eine Zeile pro Knoten. Die ganze Datei teilt sich einen PIN.

stun://eyJ2IjoxLCJnIjoi…
stun://eyJ2IjoxLCJnIjoi…
Hinweis: Sobald die Datei eine Zeile enthält, die mit stun:// oder stun: beginnt, nutzt Stun ausschließlich dieses Format. Alle anderen Zeilen werden ignoriert — auch ein danebenstehendes einfaches JSON-Array.

2.2 Ein einfaches JSON-Array

Ein Array aus Stun-Knotenobjekten. Jeder Eintrag braucht ein nicht leeres sshAddr oder proxyAddr; Einträge ohne beides werden übersprungen.

[
  { "id": "node-1", "name": "Tokio", "sshAddr": "…", "proxyAddr": "…" },
  { "id": "node-2", "name": "Osaka", "sshAddr": "…", "proxyAddr": "…" }
]

2.3 Die ganze Datei, PIN-verschlüsselt

Der Inhalt ist ein einziger verschlüsselter Umschlag ({"v":1,…}, von Stun erzeugt). Ohne PIN in der Abo-Zeile bricht der Import ab und sagt das auch.

2.4 Base64 des JSON-Arrays

Genau der Inhalt aus 2.2, Base64-kodiert. Leerzeichen und Zeilenumbrüche darin werden ignoriert.

3. Optionale Metadaten

Echte HTTP-Antwortheader haben Vorrang. Was sie weglassen, darf in der Datei stehen; was dann immer noch fehlt, behält seinen bisherigen Wert — eine Antwort ohne einen Header löscht also weder Abo-Namen noch Homepage-Schaltfläche.

content-dispositionName
Der in der Abo-Liste angezeigte Name. Nicht-ASCII-Namen funktionieren über die RFC-5987-Form. Eine Dateiendung am Ende wird entfernt, „Flughafen.yaml“ erscheint also als „Flughafen“. 
# content-disposition: filename*=UTF-8''Flughafen
# content-disposition: filename="Flughafen.yaml"
profile-web-page-urlHomepage
Fügt in der Abo-Zeile eine Schaltfläche „Homepage“ hinzu. Nur http/https werden übernommen. 
# profile-web-page-url: https://example.com
profile-update-intervalIntervall
Wie oft dieses Abo im Hintergrund aktualisiert wird, in ganzen Stunden. Ohne Angabe gelten 24 Stunden. 
# profile-update-interval: 12
subscription-userinfoTraffic
Versorgt die Traffic-Karte: verbraucht / gesamt, Upload, Download und Ablaufdatum. Alle Werte sind Bytes; expire ist ein Unix-Zeitstempel in Sekunden. Teilangaben genügen — ein fehlendes total bedeutet einfach „unbegrenzt“. 
# subscription-userinfo: upload=123; download=456; total=1000; expire=1790000000

Schreibweise der Deklaration in der Datei

  • Eine Zeile, deren erstes nicht leeres Zeichen # ist, gefolgt von Name: Wert. Leerzeichen zwischen # und Name sind erlaubt, Namen sind unabhängig von der Groß-/Kleinschreibung.
  • Kommt ein Name mehrfach vor, gewinnt der erste. Ein leerer Wert zählt als „nicht deklariert“.
  • Jede andere #-Zeile gilt als Kommentar und wird verworfen — # Flughafen ist also unbedenklich.

4. Was eine Synchronisierung an deinen Knoten ändert

  • Zusammenführen über id. Ein Knoten mit bereits vorhandener id wird an Ort und Stelle aktualisiert, eine neue id wird hinzugefügt.
  • Entfernen. Knoten, die zu diesem Abo gehören, aber in der neuesten Antwort fehlen, gelten als abgeschaltet und werden gelöscht.
  • Zwei Ausnahmen. Favoriten und der aktuell ausgewählte Knoten werden von einer Synchronisierung nie gelöscht.
  • Kein versehentliches Leeren. Entfernt wird erst, nachdem mindestens ein Knoten erfolgreich gelesen wurde. Eine Netzstörung oder eine leere Antwort lässt die Synchronisierung fehlschlagen, statt das Abo zu leeren.
  • Entdopplung über Abos hinweg. Dieselbe Knoten-id in mehreren Abos wird nur einmal importiert.

5. PIN

  • Ein verschlüsseltes Abo braucht seinen PIN, bevor überhaupt etwas importiert werden kann.
  • Fehlender und falscher PIN werden unterschiedlich gemeldet, statt still zu scheitern.
  • Der PIN wird pro Abo gespeichert. Nach einer Änderung synchronisiere das Abo erneut.

6. Aktualisierung im Hintergrund

  • Der Schalter „Auto-Synchronisierung im Hintergrund“ in diesem Panel ist der Hauptschalter.
  • Jedes Abo wird aktualisiert, sobald sein eigenes profile-update-interval abgelaufen ist (24 Stunden, wenn es keines angibt).
  • Stun prüft alle 15 Minuten und nur, wenn ein Netz verfügbar ist — es fragt den Server nicht im festen 15-Minuten-Takt ab.

7. Was die Fehlermeldungen bedeuten

  • Geben Sie eine gültige HTTPS-Abonnement-URL ein — die Adresse ist kein https:// oder hat keinen Host.
  • Der Server hat einen Fehler zurückgegeben — der Status lag außerhalb von 200–299.
  • Netzwerkanfrage fehlgeschlagen — Verbindung, Zeitüberschreitung oder TLS-Problem.
  • Keine gültigen Knoten im Abo — der Inhalt kam an, aber kein Format konnte einen Knoten daraus lesen.
  • Dieses Abonnement ist PIN-verschlüsselt. Bitte PIN eingeben. / Falscher PIN oder Entschlüsselung fehlgeschlagen — siehe Abschnitt 5.
