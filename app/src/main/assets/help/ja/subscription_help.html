購読とは HTTPS アドレス 1 つだけです。Stun はそこからノード一覧を取得し、端末への取り込み・更新・削除を自動で行います。

1. アドレスの条件

  • https:// のみ受け付けます。平文の http、ftp、sftp は拒否します —— 購読の中身が接続先サーバーを決めるため、平文だと経路上で丸ごと書き換えられてしまいます。
  • 同じアドレスは 1 件だけ保持します。再追加すると既存の項目が更新され、重複はできません。

2. 対応するファイル形式

Stun は以下の順に試し、ノードが取れた時点で打ち切ります。複数形式の混在には対応していません。

2.1 1 行 1 ノードの stun://

もっとも一般的な形式です。「テキストで共有」したときの文字列をそのまま 1 行ずつ並べたもので、ファイル全体で 1 つの PIN を共有します。

stun://eyJ2IjoxLCJnIjoi…
stun://eyJ2IjoxLCJnIjoi…
注意：stun:// または stun: で始まる行が 1 つでもあると、Stun はこの形式だけで解析します。他の行（隣にある平文 JSON 配列も含む）はすべて無視されます。

2.2 平文の JSON 配列

Stun のノードオブジェクトの配列です。各要素の sshAddr または proxyAddr が空でない必要があり、どちらも空の要素は飛ばされます。

[
  { "id": "node-1", "name": "東京", "sshAddr": "…", "proxyAddr": "…" },
  { "id": "node-2", "name": "大阪", "sshAddr": "…", "proxyAddr": "…" }
]

2.3 ファイル全体の PIN 暗号化

本文が 1 つの暗号化エンベロープ（{"v":1,…}、Stun が生成）になっている形式です。購読の行に PIN を入力しないと取り込みは中断し、その旨が表示されます。

2.4 JSON 配列の Base64

2.2 の内容を丸ごと Base64 にしたもの。途中の空白や改行は無視されます。

3. 省略可能なメタ情報

実際のレスポンスヘッダが優先です。ヘッダに無い項目はファイル内に書いて補えます。どちらにも無い項目は前回保存した値がそのまま残るので、あるときヘッダが欠けても購読名やホームページボタンが消えることはありません。

content-disposition名前
購読一覧に表示される名前。日本語などの非 ASCII 名は RFC 5987 形式で書けます。末尾の拡張子は取り除かれ、「空港.yaml」は「空港」と表示されます。 
# content-disposition: filename*=UTF-8''空港
# content-disposition: filename="空港.yaml"
profile-web-page-urlホームページ
購読の行に「ホームページ」ボタンを追加します。http/https のみ採用します。 
# profile-web-page-url: https://example.com
profile-update-interval間隔
この購読をバックグラウンドで自動更新する間隔（整数時間）。未指定なら 24 時間として扱います。 
# profile-update-interval: 12
subscription-userinfo通信量
通信量カードに使います：使用量 / 総量、上り、下り、有効期限。値の単位はすべてバイトで、expire は Unix 秒のタイムスタンプです。一部だけでも構いません —— total が無ければ「無制限」として表示します。 
# subscription-userinfo: upload=123; download=456; total=1000; expire=1790000000

ファイル内での宣言の書き方

  • 行の最初の非空白文字が # で、その後に ヘッダ名: 値 と続けます。# とヘッダ名の間の空白は任意、ヘッダ名は大文字小文字を区別しません。
  • 同じヘッダ名が複数ある場合は最初の 1 つが優先されます。値が空なら未宣言と同じ扱いです。
  • それ以外の # 行はコメントとして捨てられます —— # 空港 のように自由に書けます。

4. 同期でノード一覧がどう変わるか

  • id でマージ。 id が既にあればその場で更新し、新しい id は追加します。
  • 消えたノードの削除。 この購読に属していて、今回のレスポンスに無いノードは掲載終了とみなして削除します。
  • 2 つの例外。 お気に入りのノードと、現在選択中のノードは同期で削除されることはありません。
  • 空にはならない。 削除はノードを 1 つ以上正常に解析できた後だけ実行されます。通信が不安定だったり空のレスポンスだった場合は、購読を空にするのではなく同期自体が失敗します。
  • 購読をまたぐ重複排除。 同じノード id が複数の購読にある場合、取り込みは 1 回だけです。

5. PIN

  • 暗号化された購読は、正しい PIN を入力しないと取り込めません。
  • 未入力と間違いは別々に通知され、黙って失敗することはありません。
  • PIN は購読ごとに保存されます。PIN を変更したら、その購読を再同期してください。

6. バックグラウンド自動更新

  • パネル上の「バックグラウンド自動同期」が主スイッチです。
  • 各購読は自分の profile-update-interval が経過したときだけ更新されます（未指定なら 24 時間）。
  • Stun は 15 分ごとに確認し、そのうちネットワークがあるときだけ実行します —— 15 分ごとにサーバーへ要求しているわけではありません。

7. エラーメッセージの意味

  • 有効な HTTPS 購読URLを入力してください —— https:// ではない、またはホスト名がありません。
  • サーバーがエラーを返しました —— HTTP ステータスが 200〜299 の範囲外です。
  • ネットワーク要求に失敗しました —— 接続不可、タイムアウト、または TLS 証明書の問題です。
  • 登録に有効なノードがありません —— 本文は取得できましたが、どの形式でもノードを解析できませんでした。
  • この購読はPINで暗号化されています。PINを入力してください / PINが違うか、復号に失敗しました —— 第 5 章を参照。
